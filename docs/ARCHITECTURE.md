# Архитектура личного помощника

## Граница локального и облачного

Заметки, идеи, обычные задачи, цели, проекты планов и дни рождения сначала сохраняются в браузере. Без подключений приложение остаётся полноценным локальным PWA.

Сервер получает только данные, необходимые для выбранной интеграции: идентификатор Telegram-чата, тексты и сроки сообщений, дни рождения, соответствия локальных задач событиям Google и зашифрованные OAuth-токены. Аудио проходит через память Worker и не записывается в D1 или объектное хранилище.

## Потоки

1. Цель разбивается локальным планировщиком на 2–8 недель.
2. Пользователь изменяет задачи и нажимает «Принять план».
3. Задачи сохраняются локально. При подключённом Google backend создаёт или обновляет только события с `extendedProperties.private.zapiskiOwner=planning-assistant`.
4. Для задачи со временем создаётся Telegram-напоминание.
5. Планировщик Worker раз в минуту отправляет просроченные сообщения и проверяет дни рождения в часовом поясе устройства.

Google-синхронизация ограничена таблицей `calendar_items`: приложение не делает массовое чтение или согласование произвольного календаря. Удалённое или изменённое приложение-событие предлагается применить локально после нажатия «Проверить изменения».

## Связывание устройства

Приложение создаёт шестизначный одноразовый код и отдельный секрет опроса. Пользователь отправляет `/start CODE` боту. После совпадения сервер выдаёт один долгоживущий токен устройства; в D1 хранится только его SHA-256. Google OAuth разрешается только связанному устройству.

## Изоляция нескольких пользователей

Один публичный адрес и один Telegram-бот обслуживают несколько независимых установок. Каждый Telegram-чат соответствует одной записи `devices`; повторное подключение того же чата перевыпускает токен этого устройства. Серверные идентификаторы локальных записей вычисляются как SHA-256 от типа записи, устройства и локального ID, поэтому одинаковые локальные ID на разных телефонах не пересекаются.

Каждая строка Google OAuth, календарного соответствия, напоминания, дня рождения и голосового предложения содержит `device_id`. Читающие и изменяющие запросы всегда совмещают Bearer-токен устройства с этим владельцем. Планировщик отправляет сообщение только в `telegram_chat_id`, сохранённый у конкретной записи.

## Защита

- Telegram webhook проверяет `X-Telegram-Bot-Api-Secret-Token`.
- OAuth использует `state`, короткий срок жизни и PKCE S256.
- Refresh/access tokens Google шифруются AES-256-GCM отдельным секретом среды.
- Запросы устройства используют Bearer token; D1 хранит только хэш.
- Все SQL-запросы используют подготовленные выражения.
- CORS разрешает только перечисленные origins.
- публичное создание кодов подключения и голосовая расшифровка ограничены по частоте;
- Ручной cron и настройка webhook защищены отдельным секретом.
